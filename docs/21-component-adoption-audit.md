# Workbench 通用组件接入排查

本次检查覆盖 `packages/workbench/src/*.tsx` 及组件库中的 Schema 编辑器。以替换前的源码调用点计数；导航和编辑器的专用交互与普通表单控件分开判断。

| 控件 | 排查结果 | 处理 |
| --- | --- | --- |
| 下拉选择 | Workbench 16 处原生 select，Schema 编辑器另有 2 处 | 全部接入 SelectMenu |
| 输入 | Workbench 20 处 input、2 处 textarea | 全部接入 Input / Textarea；Schema 编辑器也复用相同基础控件 |
| 操作按钮 | Workbench 107 处原生 button | 80 处接入 Button，包括提交、取消、分页、重试、发布、激活、删除和图标按钮；27 处保留专用交互 |

## 本次接入范围

- 顶栏：语言选择、命令输入、工具图标。
- 系统日志：日志级别、命名空间、搜索、运行 ID、暂停和翻页。
- 自动化：移动端切换、参数类型、运行状态、表单、草稿恢复、发布、激活和步骤操作。
- 检查器：等待来源、连接绑定、值模式、表达式函数、布尔和枚举字面量。
- 连接与凭据：适配器、凭据类型与绑定、名称与密码字段、创建、保存、删除。
- 插件示例：验证宿主共享组件、国际化、布尔/枚举数据类型及卸载生命周期。

## 组件职责

`Input` / `Textarea` 统一样式和原生属性、事件传递。解析、校验、onInput 与 onChange 的提交时机仍由调用方或 Schema 编辑器负责。需要操纵原生焦点或文本选区时使用 `inputRef`，保持原有编辑行为。

`Button` 支持 primary / secondary / danger / ghost、图标尺寸、busy 和 disabled。原生属性传递至实际按钮；默认 type 为 button，提交按钮明确使用 submit。业务 class 保留布局用途。

`SelectMenu` 使用字符串值，提供禁用选项、方向键、Home/End、Escape、Tab 和外部点击处理。id 与 ARIA 提示传至触发按钮。浮层放入 body，依据触发位置、滚动和窗口大小定位，避免被检查器、抽屉或日志面板裁切。Boolean / Enum 编辑器负责恢复布尔和枚举原始类型。

## 保留的专用控件

剩余原生按钮用于活动导航、页签、菜单项、开关、流程节点、变量选项、面板展开/收起以及具有独立布局的导航入口。这些控件携带专用 role、aria-selected、aria-checked 或结构，不应仅为消除 button 标签而套用普通操作按钮。后续若抽取 Tabs、Switch 或 Menu，应连同键盘与焦点行为整体封装。

本次没有把页面业务状态、请求或自动化数据写入通用组件包。

## 验证方式

- `pnpm release:verify`：类型检查、单元/集成测试、生产构建、浏览器回归、配置检查。
- 系统日志在 1103×740 和 390×844 下验证：页面内容、错误覆盖层、控制台、菜单边界、焦点恢复和外部点击。
- 浏览器回归覆盖语言持久化、草稿内容保留、真实日志过滤与断线恢复、独立构建插件，以及布尔 false / 数字枚举未被错误转换成字符串。
- `pnpm release:check`：从 npm tarball 安装到独立消费项目，验证声明、组件与插件构建。不会发布 npm。
