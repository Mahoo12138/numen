# 18. 国际化服务与 Workbench 语言

## 实现边界

`@numenjs/i18n` 是 Node 与浏览器共用的 Cordis Service。直接依赖 `@koishijs/i18n-utils@1.0.1` 的语言树与回退算法，借鉴 Koishi 的点路径词条、插值、引用和插件生命周期。源码依据和差异见 [Koishi 调研](18-i18n-research.md)。

Numen 渲染纯文本，不引入 Koishi Core 的 Satori 消息树或 HTML 求值。前端用 Vue 的 provide/inject 与订阅适配服务，不引入第二套消息存储。英语与简体中文是当前 Workbench 内置语言。

国际化只影响显示。Automation 名称、Source ID、字段名、枚举值、表达式、Revision、Run payload、Credential 和 Connection 配置均不因语言切换而变更。外部插件没有提供翻译时保留其原始标题/描述；未知错误和运行记录中的原始技术信息保留原文。

## Runtime 服务

默认配置已启用服务；自定义配置可加入：

```yaml
plugins:
  i18n:
    locales: [en-US]
```

插件声明 `inject = ['i18n']`，用自己的 Context 注册词条：

```ts
import type { Context } from 'cordis'
import type {} from '@numenjs/i18n'

export function example(ctx: Context) {
  ctx.i18n.define(ctx, 'en-US', 'example', {
    greeting: 'Hello {user.name}',
    title: 'Example',
    linked: '{@example.title}: {0}',
  })
  ctx.i18n.define(ctx, 'zh-CN', { example: { greeting: '你好 {user.name}' } })

  const message = ctx.i18n.text(['zh-CN'], 'example.greeting', { user: { name: 'Ada' } })
  // 你好 Ada
}
example.inject = ['i18n']
```

- `define(owner, locale, messages)` 或 `define(owner, locale, prefix, messages)` 返回可提前调用的卸载函数；owner Fiber 卸载也会清理词条。
- 后注册的覆盖先注册的，覆盖层卸载后恢复旧值。注册时复制并展平词条，调用方随后修改对象不会改变已注册内容。
- `text(locales, path | paths, params?)` 对每个候选路径依次遍历语言回退链。全部缺失时返回第一个路径，合法空字符串视为已定义。
- 语言通过 `Intl.getCanonicalLocales` 规范化。Koishi 回退会访问父语言、同语言的其他地区及其余语言分支；例如 `zh-TW` 可回退到 `zh-CN`。`locales` 配置决定无匹配时的默认树顺序，不能简单追加到用户语言偏好，否则会改变同语言回退的优先级。
- 参数支持命名对象、嵌套自有属性和位置数组。仅字符串、数字和布尔值参与插值；缺失参数保留占位符。插入的参数不会被再次解释为词条引用或插值。
- `{@path}` 引用其他词条，循环与深度受限。原型相关键、不合法路径、重复展开路径和循环词条对象会被拒绝。
- 服务不保存全局“当前请求语言”；Node 调用方每次传入语言，避免请求之间串语言。`locales()`、`fallback()` 可用于检查可用语言与查找顺序。

## 浏览器偏好与 Vue

`startBrowserRuntime()` 在加载 Entry 前安装 i18n 与 `BrowserLocaleService`。`ctx.webuiLocale` 负责当前浏览器的语言选择：

1. 有效的显式选择（持久化键 `numen.locale`）；
2. 浏览器的 `navigator.languages`，按 Koishi 规则匹配受支持语言；
3. 默认英文。

工作台右上角可选择 English、简体中文、跟随系统。`setLocale(undefined)` 清除显式偏好。存储不可用时仍可在当前页面切换。每个 Runtime 独立持有语言状态，语言变化同步更新 `document.documentElement.lang`。

工作台提供 `@numenjs/workbench/i18n`：

```tsx
import { useWorkbenchI18n } from '@numenjs/workbench/i18n'

export const ExamplePage = {
  setup() {
    const { t, locale } = useWorkbenchI18n()
    return () => <p lang={locale.value}>{t('example.greeting', { user: { name: 'Ada' } })}</p>
  },
}
```

在 setup 中获取适配器，用其 `t()` 处理 computed、事件回调等场景；也可在渲染函数中使用导出的 `t()` 简写。不要在模块加载时翻译并缓存字符串。内置复数文案采用 `Intl.PluralRules`，日期采用当前语言的 `Intl.DateTimeFormat`。词条按纯文本交给 Vue，用户参数正常转义。

切换语言不会重新创建路由或 Draft。文字、数字、时长、日期、Reference、Template 输入保留尚未提交的编辑缓冲区，提交仍遵循原有失焦行为。

## 插件 Entry 与词条热更新

Node 插件与浏览器 Entry 是不同 Context。需要前端显示的词条必须随 Entry 注册，不会自动从服务端传送整个字典。

Entry 内调用同样的 `ctx.i18n.define(ctx, ...)`。加载器将词条写入暂存区，与 Page/Renderer 等扩展快照一起提交；同步订阅者看到的 Page 和词条属于同一代。失败的新 Entry 不会改变旧字典。旧 Fiber 随后卸载时仅删除自己持有的词条，不能误删新一代。暂存期间的读取仍读取当前生效字典，应把翻译留到渲染时执行。

Page 可声明 `titleKey`，同时保留原始 `title`。插件可以为插入目录提供以下词条路径，缺失时回退原始元数据：

```text
workbench.capabilities.<capability-id>@<version>.title
workbench.capabilities.<capability-id>@<version>.description
workbench.capabilities.<capability-id>@<version>.fields.<field-name>
workbench.capabilities.<capability-id>@<version>.fieldDescriptions.<field-name>
workbench.controls.<control-id>@<version>.title
```

扩展 Control 同样支持 description、fields 和 fieldDescriptions；内置 Control 使用不带版本的 `wait`、`if`、`parallel`、`race`、`foreach`。建议自定义页面使用插件自己的词条命名空间，避免覆盖其他插件。

服务端错误 code 保持不变。Workbench 对已知 code 提供中文说明并保留原始 message 作为技术细节；未知错误不根据英文文本猜测翻译。日志、用户配置描述、第三方 Schema 标题与原始运行数据不自动翻译。

## 验证

- 核心：Koishi 地区回退、路径优先、插值和引用、安全输入、覆盖恢复、Fiber 清理、快照代际。
- WebUI：浏览器语言匹配、偏好持久化、存储受限、Context 隔离、Page/词条原子激活与失败回退。
- Workbench：中英文键与参数一致、静态词条引用完整、Vue 渲染隔离、HTML 转义、元数据不修改输入值。
- 生产构建 Playwright：中文首次进入、中英文切换、保持聚焦输入、发布并校验不可变 Revision、刷新恢复偏好、桌面及 390px 手机布局、无浏览器错误。

运行 `pnpm release:verify`。`0.1.0` 标签固定在引入 i18n 之前的本地发布基线；i18n 提交不移动该标签。
