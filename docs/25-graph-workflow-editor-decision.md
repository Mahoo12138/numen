## 2. 需要确认的第一版基线

以下是建议，不作为已经批准的协议。确认前只推进审查、原型和不依赖这些决定的工作。

### 2.1 Source 承载：显式 Graph Control

推荐保留 `AutomationSource` 外壳，新增有版本标识的 Graph Control。Graph 可以作为根流程；第一批执行验证只接根图，验证通过后再接显式循环作用域。

Graph Source 持有稳定节点、具名端口、语义连接及表达式，作为唯一业务真相。画布库的节点/边是投影，不另存能决定执行的图副本。Graph lowering 到专门的图 IR，不降级成旧树。

旧 Structured Source 和旧 IR v1 保持原样。含 Graph 的新固定快照建议标记 protocol v2 / IR v2；新运行时同时读取两代，在执行前拒绝不支持的版本。不能把含新语义的快照继续标成 v1，也不能假设现有旧二进制已经具备版本拒绝能力：G1 需验证数据库升级后的防降级边界，无法安全打开新数据目录时明确拒绝启动。具体 JSON 字段在基线确认后随编译纵向验证冻结。

独立 Graph AutomationSource 也是可行替代，但会同时分叉触发器、输入、策略、文档及快照管线；目前没有足够收益抵消这部分兼容成本。显式 Graph Control 不意味着图必须能转换回树。

### 2.2 依赖与调用基数

- 普通边声明端口关系及执行依赖。表达式声明数据路径；不自动暗中补边。
- 新增引用缺少依赖时，Draft 保留引用并诊断；用户可通过一次明确命令同时补上依赖。编译器权威检查二者一致。
- 普通节点在一个图作用域实例内最多一个逻辑 Execution；多条出边共享结果。重试增加 Attempt，不新增逻辑节点调用。
- Graph 有显式激活入口；起始节点必须明确连到该入口。断开末条入边后保留节点，但不自动把它提升为入口。不可达节点保留在 Draft 并产生阻止执行的诊断。其他节点依据明确的输入规则就绪。坐标、节点数组顺序、完成顺序不决定业务依赖。
- 推荐第一版就绪节点共享现有 Scheduler 全局并发上限（当前默认 16），暂不另设每图配额；界面说明无依赖节点可能并发，需要先后顺序必须连边。
- 数组仍是一份数据，普通 Capability 不隐式逐项调用。只有显式 ForEach 创建迭代作用域。
- 逻辑 Execution 去重不承诺外部副作用严格一次；OUTCOME_UNKNOWN 继续阻止不安全重放。

### 2.3 条件与汇合

图节点结果至少区分：未就绪、已产生值、已跳过、失败、取消、结果不确定。`null` 和 `[]` 都是已产生值，不能充当其他状态。

建议首版只开放以下可明确校验的两类汇合：

| 模式 | 就绪与输出规则 | 明确拒绝或传播的情况 |
|---|---|---|
| 全部输入 | 所有必需来源成功后，按唯一输入名组成对象 | 重名输入被拒绝；失败不变成缺字段；必需来源 skip 导致下游 skip |
| 条件所选输入 | 所有候选来源已完成或已明确 skip，且恰好一个被选来源成功后，输出该来源值 | 编译验证候选路径互斥；多条成功不能退化成取最快或最后一条；全 skip 继续传播 skip |

普通节点的必需控制输入若被跳过，节点也被跳过；条件汇合显式处理互斥路径。被选路径失败采用 fail-fast，不伪装成 skip，不继续返回部分成功对象。复杂的非互斥“任意一个成功”仍属于 Race 语义，不借条件汇合隐式引入。

### 2.4 循环与结果收集

普通图保持 DAG；回边、跨后代作用域连接和越界引用由编译拒绝。循环沿用显式 ForEach。

建议首版收集循环体显式输出，保留输入序号/迭代身份，按原始输入顺序产生数组；空输入产生 `[]`。嵌套循环以作用域身份隔离。首版单项失败采用 fail-fast，不开放静默丢弃失败项或部分成功。集合后的通知只执行一次。

### 2.5 测试样例与局部执行

建议首版样例独立持久化，固定 Source 节点身份、契约版本、来源快照/Execution、创建时间和数据完整性。人工样例与从完整执行数据导入的样例必须明确区分。脱敏/截断投影不可导入为完整原值。

先支持可验证的普通节点及无环子图；“执行至节点”计算依赖闭包，“只执行节点”要求固定输入满足契约。执行预览列出真实调用、样例替代、外部写入。只在明确的测试快照中附带样例与范围，正式触发和激活 Revision 不读取它们。

含 ResourceRef 的样例首版建议明确拒绝创建/导入，直到持久化资源所有权和失效规则可验证；不得存一个临时地址后宣称可复用。复杂循环内部单次迭代调试后置。样例变更和局部测试不改变正式激活状态。

## 3. 执行实现必须守住的条件

1. 图作用域具有持久化身份；节点就绪/skip 等事实可由数据库恢复。
2. `(graph scope execution, authored node identity)` 有数据库层唯一约束；创建节点 Execution 和接受输入/结果在事务中协调。
3. 多路完成同时到达、重复 dispatch、服务重启均不能为同一节点创建第二个逻辑 Execution。
4. Graph 节点复用 Capability Provider、Connection、Attempt、超时、重试及 Resource 提交路径。协调器不另起不可恢复的临时执行器。
5. 完成事件经过 Execution generation 和作用域取消状态检查；迟到 Provider 结果不重新激活已取消图。
6. 图输入绑定从准确作用域和显式依赖读取，不能使用整个 Run 的“最后一次同 ID 输出”。交叉依赖不能依赖单一 parent 链。
7. 恢复时依据固定快照和已接受结果调度；历史快照不重新编译，不借当前插件 Source 更改历史逻辑。
8. 前端和服务均显式处理不支持的协议，保留原数据；删除连接不删除节点或参数。

持久化实现优先让不可变计划保存边，以节点的耐久终态和条件输出推导边是否选中，避免重复保存两套权威结果。具体采用图成员表还是扩展 Execution 状态由 G1 迁移验证决定；两者都必须真实记录 skip，不能用 `COMPLETED(null)` 替代。

当前后继创建机制会为每个前驱创建新随机 Execution；当前 Fork/Join 仅协调结构化 scope 的分支，支持 all/first_success，但不能表达任意多输入依赖。因此两者都不能直接承担多输入图调度。需要独立图协调路径，继续复用耐久执行基础。

## 4. 完整编辑区的交互边界

- 默认：既有全局导航 + 文档标题/保存状态 + 大画布 + 单个选中节点的紧凑配置。节点显示名称、能力、端口标签、Connection 摘要和状态，不显示参数全文。
- 大纲、诊断和运行细节按需展开；避免默认同时挤进所有侧栏。
- 节点聚焦：输入来源、参数映射、输出参考相邻展示；退出后回到原选择和视口。窄屏使用单区切换，保留选择与未提交字段保护。
- 连线、重新连接、插入、断开和删除经过领域命令；菜单/键盘提供鼠标替代路径。无效草稿可以保存，测试/发布必须编译。
- 拖动过程只更新会话坐标；结束后一次提交 Presentation、一次 Undo。框选布局和自动布局也是一次文档操作。
- Schema、样例和历史输出标明来源；Draft 与输出快照不一致时明确显示旧版本参考。未知动态路径不显示为已验证。
- Connection 新建/修复返回原节点和 Slot，重新校验存在性、类型兼容及原字段未被他处修改后再绑定。
- 旧 Structured 流程继续使用已有编辑器；只读投影和显式转换入口后续接入。不自动切换所有新建流程默认模式。

画布库待原型验证端口、容器、键盘替代、100/300 节点和生命周期后选定；选库不决定上述语义。

当前 Run Flow、快照 Source 及比较的节点遍历上限为 250；已有 Execution 列表分页并不解决这个限制。G5 的 300 节点末端检查必须补定点读取或分页证据，不能只增大一次响应或复用编辑区容量数字。

| G3-a | Object/Array 表达式及统一条件函数 | 混合引用/字面量/模板/函数；非法输入保护；编译与执行同义 |
| G3-b | 输入/参数/输出聚焦区、Connection 返回、循环收集 | 动态字段、空值、并发乱序、嵌套循环、失败恢复、通知次数 |
| G4 | 持久化样例、局部测试范围与预览 | 样例完整性/版本/删除、依赖闭包、调用计数、正式运行隔离、副作用不安全重放拒绝 |
| G5 | 显式转换、比较/恢复、性能与生命周期收尾 | 旧快照往返、卸载/重载、断线协调、跨浏览器关键路径、100/300 节点及末端定位 |

### 有区分度的执行验收

- 天气+日程：两者各一个 Execution；汇总必需输入齐全后一次执行；通知和保存共享同份简报。
- A/B/C→D/E：D 依赖 A+B，E 依赖 B+C。用受控延迟保持 C 未完成时 D 必须可运行；B 只有一次逻辑执行。不能仅断言最终结果正确。
- 条件：true/false、未选 skip、所选返回 `[]`/`null`、所选失败；汇合不死等、不抹掉错误。
- 集合：空输入、并发逆序完成、嵌套循环、失败与重启；输出顺序和来源不串项，末端通知一次。
- 恢复：一个前驱已完成另一个未完成时停机，恢复后复用接受结果；取消中晚到结果不能再启动下游。
- 断线：删除写入节点最后一条入边后，节点和参数仍可 Undo/保存，但测试/发布报告不可达；不能因无入边而意外执行写入。
- 局部测试：上游样例固定后重复测试转换节点，计数器证明外部查询/写入没有被重放；正式执行不使用样例。
